NayiSaans: Complete Architecture and Digital Twin Data Flow

An Explainable Digital Twin for Smoke-Free Recovery

Accuracy notes for reviewers
  • Experimental recovery-support prototype — not a medical device.
  • Nicotine exposure and webcam heart rate are estimates, not clinical measurements.
  • Craving-risk model trained on a literature-informed synthetic dataset (3,000 samples) — not clinically validated.
  • Recovery Coach is rule-based and state-aware, not an LLM.
  • Raw webcam video is never uploaded — only derived BPM and signal quality are sent to the backend.

5 · Digital twin engine — central brain

recompute_twin(user_id)

Runs after: onboarding completion · "I smoked" check-in · "I resisted" check-in · successful physiology/BPM check

Inputs

  • Recovery profile: start date, quit reason
  • Substance profile: usual first-cigarette time
  • Usage logs: timestamps of logged cigarettes
  • Recent check-ins: stress, smoked/resisted pattern
  • Latest physiology log: BPM and signal quality
  • Current time of day

Outputs → Twin State

  • Smoke-free streak, best streak
  • Nicotine exposure % + 12-hour series
  • Craving-risk %, risk level (low/moderate/high)
  • Confidence (low/moderate/high)
  • Top "why this risk" factors
The twin updates after key logged events; it is not continuously recalculated in the background.

6 · Model layer

A. Nicotine exposure model

nicotine_model.py

  • Exponential decay: C(t) = C₀ × e^(−kt)
  • Approx. half-life: 2 hours
  • Each cigarette creates a decay curve
  • Curves summed, capped at 100%
  • Outputs: current exposure + 12h chart
Relative exposure estimate, not a blood test.

B. Craving-risk ML model

craving_model.py

  • scikit-learn logistic regression
  • NumPy synthetic dataset: 3,000 samples, seed 42
  • Features: hour of day, usual-time match, days since last cigarette, stress 1–5, smoked/resisted ratio, HR deviation from 70 BPM
  • Outputs: risk %, level, confidence
  • Explainability: SHAP if available, else coefficient fallback
e.g. "Reported stress increased your estimated risk."

C. Webcam rPPG BPM estimator

rppg.js

  • Runs fully in browser
  • Green-channel pixel variation + peak counting
  • Rejects poor signal / bad lighting / implausible BPM
  • Outputs BPM + signal quality

Flow 1 — Signup and onboarding

User signs up
→
bcrypt hashes password
→
User record saved
→
JWT returned, saved in sessionStorage
→
Onboarding data saved
→
Twin engine runs
→
Dashboard becomes available

Flow 2 — Daily check-in and twin update

User chooses "smoked" or "resisted"
→
Frontend: POST /checkin
→
Backend saves CravingLog
→
If smoked, also save UsageLog
→
Twin recomputes nicotine, streak, risk, confidence, explanations
→
Dashboard & twin show updated state

Flow 3 — Risk to action

Twin predicts elevated risk
→
Dashboard shows top risk factors
→
Backend prioritises relevant recovery tasks
→
User completes task, logs craving before/after
→
TaskCompletion stored
→
Analytics calculates average craving relief over time
Privacy by design: raw webcam video is not stored. NayiSaans provides experimental estimates for recovery support, not diagnosis.
